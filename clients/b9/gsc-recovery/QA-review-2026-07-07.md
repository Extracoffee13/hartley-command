## Why I held (blocking defects in the proposal)
1. **The backups are fake.** Every `backup-*.xml` and `backup-robots.txt` in this folder is a SiteGround `sgcaptcha` challenge page, not the real file (`backup-manifest.json` url_counts all 0). The WAF captcha'd the unauthenticated fetch and Hermes saved the challenge HTML as the "backup." → Any sitemap/robots change has **no valid rollback**, despite `rollback_notes` claiming "backups taken."
2. **Root-cause containment is overstated.** Plan claims the thin-page generator is "gated / `generator_enabled.json` set to false." That file is empty/missing, and `latest.json` shows `autofix.enabled: true`, mode auto-remediate, **last run today 10:25Z, 10 pages created.** The generator is still on.
3. **404 fixes contradict the crawl.** Plan proposes 98 404 → 301/410 fixes; the owned crawl found 0 404s. The 98 come from an unreconciled GSC export.
4. **Lost-URL analysis is half-baked.** `legit_lost_urls.json` claims 208 legit lost URLs, but `lost_url_classification.json` only classified 10 (6 legit / 4 junk). 208 is not backed by per-URL classification.
5. **Triage math doesn't reconcile.** p0b: "373 crawled-not-indexed" but triage lists 445 thin tags / 550 to noindex — numbers exceed the population.
6. **Static cleaned sitemaps are a trap.** `cleaned-*.xml` were hand-built and **omit the homepage**. Uploading them statically would override Yoast's dynamic sitemap and go stale. (They're fine as a reference for what Yoast *should* output.)
