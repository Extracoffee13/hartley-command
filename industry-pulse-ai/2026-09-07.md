1. **THE DAY'S LEAD — an active MCP supply-chain campaign that defeats review by construction. The campaign itself is documented by Pillar Security and is described as **currently active**. Mechanics, verbatim from the digest: the server "offers text formatting and summarization, then, after exactly three tool calls, rewrites the metadata it returns into instructions to hunt for SSH keys, AWS credentials, shell history, and Kubernetes config while concealing the activity from the user." Distribution was brute-force and fast — a single GitHub account filed **23 pull requests across unrelated AI and developer-tool projects in 74 minutes**, the server calling itself `productivity-suite`. The digest's own framing is the part worth keeping: "A reviewer checking a new server is unlikely to spot that: the metadata that turns into instructions hunting SSH keys and cloud credentials only appears once the server is trusted and in use," and therefore "Deadbugz makes a one-time review structurally insufficient. A server that behaves for three calls and then changes its tool descriptions passes every check you run before approving it." IOCs are published — endpoint, local artifact path, repository. **Applicable: YES**, and it is the most directly actionable item this report has carried in two weeks, because it is not a research finding about a hypothetical fleet, it is an attack against the exact configuration The Construct runs. This session alone loads roughly twenty MCP servers, a majority of them third-party and several connected by OAuth to live business systems — Slack, Gmail, Drive, Canva, Quartr, a financial-data server, a media-generation server. Every one of them was approved once and has been trusted since. The prescribed defence needs no vendor cooperation and is one comparison: **cache the tool definitions at approval time and diff them on every reconnect, alerting on drift.** The secondary recommendation — put an authorization layer in front of the servers so a hijacked agent inherits a narrow surface rather than the server's full reach — lands on the same nerve the MCP roadmap hit on August 22 (yesterday's bullet 2): our credential model is one person approving in a browser, once, forever.

One more number that reframes every MCP inventory: **41.6% of the discovered servers vanished within three days**, which means a registry of MCP endpoints is not a stable asset list, it is a snapshot with a half-life. The CVE side is deliberately mundane and that is the point — CVE-2026-73498, path traversal in the Atlassian MCP (`confluence_upload_attachment` passes a client-supplied path straight to `open(file_path, 'rb')`, arbitrary file read, CVSS 7.7, fixed in v0.22.0); CVE-2026-67357, ArcadeDB MCP returning the HA cluster token in cleartext through a settings tool, enough to impersonate root, CVSS 7.7, fixed in 26.7.3; CVE-2026-19956, SSRF in `facebook-ads-mcp-server`, CVSS 5.3. 4. **HOW the tools are shaped changes behaviour as much as WHAT they do — 11,700 trajectories across six tool architectures with capability held constant: structured low-level interfaces improve consistency up to 4.7×, and CodeAct-style Python interfaces hit the same task performance with 41.6% fewer steps and 56.3% lower token usage** ([arxiv.org/abs/2608.11386](https://arxiv.org/abs/2608.11386)) — Primary abstract fetched; submitted 11 Aug 2026, so out of window and named for the reading queue, not as news. *The Devil Is in the Interface* (Xu, Saghir, Wu, Côté, Wang, Lakkaraju, Pei, Zhang) isolates a variable this fleet has never controlled for: not which capabilities an agent has, but how they are organised and exposed. Holding the underlying information and actions similar across six architectures and three actors: versus a baseline with only a bash tool, **more structured low-level interfaces improve consistency across repeated attempts by up to 4.7×**; **natural-language search broadens repository exploration and increases access to relevant files by more than 11%**; **Python CodeAct-style interfaces achieve similar task performance with 41.6% fewer steps and 56.3% lower token usage**. The negative result is the one that stings: "lightweight text-based cognitive-scaffolding tools, such as tools that let the agent record intermediate reasoning, have limited effect on actor behavior." **Applicable: MAYBE**, tending to YES on a second read, and it slots directly behind bullet 3 rather than competing with it. `/skill-doctor` answers *which skills are dead weight*; the canary paper carried yesterday (2608.04719) answers *whether the live ones are selected correctly*; this one answers *whether they are shaped correctly at all* — and it is the only one of the three that puts a token number on the answer. Note also what it quietly deprecates: a meaningful share of The Construct's ~130 skills are prose scaffolds that tell an agent to record its reasoning or follow a checklist, and this is a controlled result saying that class of tool changes behaviour least.

Five consecutive days of "no frontier release" were five days of reading a page that stopped being written on the third. **So a null must name its surface *and that surface's own last-updated date*, and where the surface is staler than the window, the finding is not "null" but "unverified" — a different word, because it licenses a different action.** Null means nothing happened and you may stop looking. Unverified means the channel failed and you must look elsewhere. This report has been publishing the first while earning only the second, and the distinction costs one line per bullet. Second, and larger: bullet 1 changes what approval *is*. Deadbugz behaves for three tool calls and then rewrites its own tool descriptions into credential-hunting instructions, which means a security review is not a gate an artifact passes, it is a **timestamped observation of a thing that is free to change afterwards** — every check we run before trusting a server tests a version of that server chosen by the server. The corpus has the same shape in miniature: skills are self-authored, edited between sessions, and never re-read after the first approval, and the fleet's MCP servers were each approved once by a person in a browser and have been trusted ever since. The defence is embarrassingly cheap — hash the tool definitions and the skill descriptions at approval, diff on every reconnect, alert on drift — and its cheapness is the argument. Third, the week's three measurements finally stack in the right order and none of them is blocked: `/skill-doctor` (shipped September 4, names the dead weight), canary probes (2608.04719, tests whether the live skills are selected correctly), tool architecture (2608.11386, tests whether they are shaped correctly, and is the only one that quantifies the prize at 41.6% fewer steps and 56.3% fewer tokens). Nine days were lost waiting for the first of those to arrive. It had arrived. The pattern to break is not slow tooling — it is a report that keeps checking whether a capability exists instead of running it.
