4. **"PIN THE PROTOCOL VERSION" NOW NAMES A SPECIFIC VERSION AND A REAL REASON — MCP has gone FULLY STATELESS in the 2026-07-28 spec, the largest revision since launch, and it changes what an MCP server even is** ([blog.cloudflare.com](https://blog.cloudflare.com/mcp-v2/)) — The 2026-07-28 specification shipped with updated TypeScript, Python, Go and C# SDKs and removes the stateful client-server connection the protocol was built on. In practice that deletes sticky-session routing, held-open streams and message replay: Cloudflare reports servers now running in a single Worker with no sticky sessions, open streams or Durable Objects, with its Agents SDK supporting the spec from day zero and in production with Sentry and Linear. It also enables richer flows including elicitation for approvals. Source-quality note: this is a vendor blog about a spec whose statelessness is maximally convenient for that vendor's edge-worker architecture, so treat the engineering claims as accurate and the "agent infrastructure works like the rest of the web now" framing as marketing. **Applicable: YES** — YES, and it converts one line of standing action (b) from box-ticking into a decision. Pinning a protocol version is dull housekeeping if the protocol is stable and load-bearing if the protocol just changed underneath — and a stateless protocol is a different security object than a stateful one, because per-request authorisation becomes possible where session-scoped trust used to be assumed. Read against bullet 2 the pairing is uncomfortable and useful: Deadbugz exploits the fact that a server's ANSWERS can change between calls, and the spec has just made every call independent, which cuts both ways — no session state for an attacker to poison, and no session continuity for us to audit against. The practical instruction for (b) is now specific rather than generic: pin to 2026-07-28, and take the elicitation-for-approvals hook seriously, because an approval prompt is the cheapest incident log we will ever get and it comes from the protocol rather than from us.
