1. **Correction to yesterday's brief — the Jul 28 MCP spec is *not* a breaking deadline, and the beta SDKs to test it have been out since Jun 29** ([blog.modelcontextprotocol.io](https://blog.modelcontextprotocol.io/posts/sdk-betas-2026-07-28/)) — the official SDK announcement is explicit: "for existing clients and servers nothing breaks today, and nothing breaks on July 28 either. This is merely the date when the normative specification text is published and is not a switch-off for any implementers relying on the current protocol version." Betas are available for all four Tier 1 SDKs — Python `mcp` v2 (`2.0.0b1`), TypeScript v2 (split packages, ESM-only, `@beta`), Go (`v1.7.0-pre.1`), C# (`2.0.0-preview.1`) — and opting in is deliberate at every step: unpinned installs still resolve to stable, TypeScript/Go don't change what they speak over HTTP until you wire the transport, and clients speaking `2026-07-28` fall back to the `initialize` handshake against `2025-11-25` servers. The SDK v2 majors are a *separate* breaking change on your own schedule; TS v1.x gets bugfixes and security patches for at least six months. Also worth pinning: standard error codes change (missing resource returns JSON-RPC `-32602`, not the MCP-custom `-32002`) and MRTR lets tools return `InputRequiredResult` to ask mid-call with no long-lived stream. **Applicable: YES** — our Jul 15 brief said every MCP server we run "has 13 days to be ready" and "either follows its SDK through the window or breaks." That was wrong, and it was wrong in the direction that manufactures urgency. Nothing switches off. The real action is smaller and duller: add `mcp>=1.27,<2` upper bounds now so the stable Python v2 doesn't surprise us, pin exact versions if we test a beta, and check whether anything in our fleet string-matches `-32002`.

2. **Claude Code 2.1.210 is a security + memory-integrity release that lands on our exact configuration** ([releasebot.io](https://releasebot.io/updates/anthropic/claude-code)) — four fixes hit The Construct specifically. The Agent tool is now hardened against indirect prompt injection via content a subagent read. `isolation: 'worktree'` subagents could run git-mutating commands against the main repo checkout instead of their own worktree — fixed. The `ultracode` keyword opt-in was firing on non-human-originated input such as webhook payloads and relayed PR comments — fixed. And memory writes that leave a MEMORY.md index over its read limit now produce an explicit error instead of silently truncating. Alongside: plugin-provided MCP servers no longer torn down when MCP servers re-sync mid-session, unmatched `$1`/`$2` placeholders in skills and commands are preserved instead of silently stripped, and the auto-mode permission classifier defaults to Sonnet 5 for external sessions. **Applicable: YES** — the MEMORY.md fix is the one to sit with. `~/.hermes/memories/MEMORY.md` is our index, it grows every day, and until this release an oversized index truncated *silently* — meaning agents may have been reading a partial memory and none of us would have seen an error. The worktree-escape fix matters given the standing rule that only Hermes holds the Mac GitHub credential; a worktree subagent reaching the main checkout is exactly the boundary that rule exists to protect. And the `ultracode`-on-webhook fix is a reminder that scheduled and relayed input is not human input — this brief is itself non-human-originated.

3. **Cowork on web and mobile runs on Anthropic-hosted remote sessions — scheduled tasks now run with no device online at all** ([claude.com/blog](https://claude.com/blog/cowork-web-mobile)) — announced Jul 7 and rolling out in beta over several weeks starting with Max: Cowork sessions move to claude.ai and iOS/Android, saved to your Claude account, with work continuing in the background after you close the laptop. The execution model is the change, not the surface: remote sessions hosted on Anthropic's servers can keep working — and run scheduled tasks — with no device online. Chat and Cowork now share one home tab, sidebar, search, and Projects & Artifacts. Doubled Cowork usage limits are extended through Aug 5. Related, same day: Claude Code and Cowork went to public beta in a FedRAMP High environment via Claude for Government Desktop ([claude.com/blog](https://claude.com/blog/bringing-claude-code-and-claude-cowork-to-government)). **Applicable: YES** — this is a structural fix for a constraint we designed around rather than solved. `lens-daily-scan` carries "survives Cowork being closed overnight" in its own description, and the multi-fire 5:34/9:34/13:34 schedule with idempotent skip exists precisely because we could not trust a fire to happen when the machine was asleep. Remote-hosted scheduled tasks remove the premise. Worth testing before we simplify anything — but if it holds, the whole multi-fire-plus-skip pattern is scaffolding we can take down.

**PRAXIS lesson:** The most important thing found today was our own error. Yesterday's brief turned a spec publication date into a countdown to breakage, and the primary source says plainly that nothing switches off on Jul 28. Nobody fact-checks the scan, which means the scan must fact-check itself — and it is most dangerous exactly when it is most useful, because an urgent-sounding deadline is the kind of item that gets acted on without being re-read. Note the asymmetry in today's four items: the two that matter (a silent MEMORY.md truncation, an agent that reached the wrong git checkout) were quiet bugfix lines in a changelog, while the loud calendar item was overstated. Signal and volume are uncorrelated. Verify the claim, then set the temperature — in that order, because a scan that inflates is worse than a scan that misses.
