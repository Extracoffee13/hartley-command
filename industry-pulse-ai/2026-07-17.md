2. **The real MCP deadline: spec `2026-07-28` goes final in 11 days, and it is the largest breaking revision since launch** ([blog.modelcontextprotocol.io](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)) — read from the primary source, not an aggregator: the release candidate was **locked May 21, 2026** and the final specification **publishes July 28, 2026**. The protocol core becomes stateless — the `initialize`/`initialized` handshake and the `Mcp-Session-Id` header are both removed (SEP-2575, SEP-2567), with protocol version and client info moving into `_meta` on every request. Streamable HTTP now requires `Mcp-Method` and `Mcp-Name` headers so gateways can route without body inspection. Extensions become first-class (reverse-DNS IDs, independent versioning), with MCP Apps (server-rendered sandboxed HTML UIs) and Tasks shipping as the two official extensions — and Tasks is **reshaped**, so anyone who built against the `2025-11-25` experimental Tasks API must migrate. **Roots, Sampling, and Logging are deprecated** (annotation-only; they keep working for at least twelve months). Tool schemas lift to full JSON Schema 2020-12, and the missing-resource error code moves from the MCP-custom `-32002` to standard `-32602`. **Applicable: YES** — this is the deadline the Jul 15 fire hallucinated and then had to retract; here it is, real, dated, and sourced from the maintainers' own post. Every MCP server The Construct runs or depends on sits on the far side of a breaking change in 11 days. Two concrete exposures: any of our code matching the literal `-32002`, and any skill assuming session-scoped state that the transport will no longer carry. The correct move this week is an inventory of our MCP surface against the draft changelog, not a scramble on Jul 29. Note the shape of the Jul 15 error — the deadline was real, the date was invented; the fix was never skepticism, it was reading the primary source.
