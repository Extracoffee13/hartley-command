1. **RE-VERIFIED UNDER PRESSURE AND IT HOLDS - Claude Code 2.1.257/2.1.258 (Sept 1) did ship `Containment Escape`, `blockReadsOutsideWorkingDirectories` and `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`; the second-fire re-check appeared to falsify this bullet and instead falsified the page it was checked against (see bullet 5)** ([github.com](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)) — Carried from the 05:12 fire and re-verified at the second fire against the upstream CHANGELOG.md in the anthropics/claude-code repository. Version 2.1.257, dated September 1 2026, is the release that made Fable 5.1 the default Fable model, and beside that headline it carries three changes that matter more to a running agent fleet than the model swap does. First, auto mode gains a Containment Escape rule: cloud metadata-credential fetches, egress evasion, and cross-tenant reach are no longer auto-approved unless the environment marks them expected. Second, a one-time prompt fires before the first file read outside the configured working directories, with `permissions.blockReadsOutsideWorkingDirectories` available to block such reads outright. Third, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` applies `CLAUDE_CODE_SUBAGENT_MODEL` (or the main model) to every subagent, overriding per-spawn and agent-definition model choices - a cost ceiling or a compliance requirement that all delegated work run on a named model. Also in 2.1.257: `timeFormat`/`timeZone` settings (12-hour, 24-hour, 24-hour UTC, or a strftime pattern) and `s` in `/effort` for session-only effort changes. 2.1.258 followed the same day with two fixes: Claude Code failing to launch on macOS 12 Monterey (a regression introduced in 2.1.255), and remote and scheduled sessions failing with 'user messages must have non-empty content' after a re-sent permission approval could not be applied. Anthropic's own auto-mode engineering write-up states auto mode blocked about 89% of dangerous commands in testing, so the Containment Escape rule narrows a gap in a control that was already imperfect rather than adding a new one. **Applicable: YES** — YES, and it remains the day's most actionable item because two of the three are levers Bobby can pull on the fleet as configured today. `blockReadsOutsideWorkingDirectories` is first: this Cowork session alone mounts nine folders including `.Trash`, iCloud Drive, and the whole Documents/Claude/Projects tree, and a per-agent working-directory boundary is exactly the containment a fleet with that much reach currently lacks. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` is a direct cost and consistency lever - The Construct spawns subagents heavily and per-agent model overrides accumulated across ~130 skill definitions are precisely what nobody audits; one environment variable pins every subagent to a known model. The Containment Escape rule needs no action but changes what auto mode does unattended, which matters for the scheduled and cron-driven jobs that run without Bobby watching - and the 2.1.258 scheduled-session fix matters for the same reason, since this report is itself a scheduled task. The macOS 12 launch regression in 2.1.255 is worth knowing before any fleet upgrade lands on an older Mac. Stated as a limit, unchanged from this morning and now twice as pointed: this report still has not read `claude --version` on the fleet, none of these controls exist below 2.1.257, and that one command is the prerequisite to every action above.

**PRAXIS lesson:** Primary is not a page, it is a chain, and the last link is the one to read. This morning's lesson was to enumerate a vendor's channels rather than assume one page covers the vendor. The second fire applied that rule, opened the Claude Code docs changelog, found the day's lead bullet absent from it, and drafted a correction that would have replaced a true finding with a false one - because the vendor's own rendered page lags the vendor's own upstream by seven releases, and says so in its own header. Three consecutive days have now produced three costumes of one error: trusting an aggregator over a primary, trusting one channel as the whole vendor, and trusting a rendered page over the source it names. The rule that covers all three: follow the provenance to its end, and check a channel's build date before believing its silence. A source is only as current as its last build, and freshness is a property to verify, never one to infer from authenticity.
