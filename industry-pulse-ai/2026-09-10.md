3. **THE BUILT-IN BROWSER IS NOT AN ANNOUNCEMENT TO US — IT IS ALREADY IN THIS SESSION, AND IT COLLIDES WITH A LOCKED OPERATING RULE** ([claude.com](https://claude.com/blog/cowork-built-in-browser)) — Cowork now runs its own browser inside the desktop app: when a task involves a website, a browser opens in a side panel and Claude opens sites, reads pages, clicks, types and fills forms in view, with the same browsing capabilities as Claude in Chrome but independent of whichever browser the user normally runs. It reached Pro, Max and Team on macOS, Windows and Linux with Enterprise admins able to enable it org-wide, and when the desktop app is online the built-in browser is also available in Cowork on web and mobile. The isolation property is the load-bearing one: **Claude cannot see your tabs, bookmarks or saved passwords unless you explicitly import logins into it, site by site.** **Applicable: YES** — YES, and uniquely among the items this report carries, verification cost nothing: the `mcp__Claude_Browser__*` toolset is live in this very session alongside `mcp__claude-in-chrome__*`, so this is observed rather than reported. The collision is with two standing rules of ours that were written when only one browser existed. Our locked rule is **never open a new Chrome window or tab — always attach to the already-open Chrome** and its existing tabs, and a whole family of skills (`review-open-browser-tabs-first`, `chrome-automation-user-visibility`, `hermes-real-browser-only`) exists because Bobby's *paid, logged-in* subscriptions — Higgsfield, HBR, LinkedIn, GBP, SiteGround — live in that one Chrome profile. The built-in browser is a **second, empty, credential-isolated profile**, and that is both the opportunity and the trap. Opportunity: the consumer-LLM visibility scan (ChatGPT / Claude / Perplexity / Gemini for `brand-insights/latest.json`) is exactly the job that should NOT run in Bobby's authenticated Chrome, because his logged-in history is a confound in a brand-visibility measurement and because driving his real tabs renders them blank to him — a documented, repeatedly-costly failure. A clean isolated profile is a *better instrument* for that scan. Trap: any credentialed job — GBP, SiteGround cache purge, Higgsfield generation, LinkedIn posting — will silently fail or dead-end in the built-in browser, because the logins are not there and must be imported site by site. So the rule needs a split rather than a replacement: **credentialed work stays in the attached Chrome; measurement work moves to the built-in browser.** That is a one-line amendment to three skills and it removes a real confound from the only scan we run that produces a client-facing number.
