1. **Claude Code's Aug 21 release hardens the exact surface yesterday's CVE exposed — synced Skills are sanitized and DON'T execute locally, plugin catalogs get minted-token fetches, and permission hooks re-check mutated input** ([support.claude.com](https://support.claude.com/en/articles/12138966-release-notes)) — Anthropic shipped a broad Claude Code update on Aug 21 whose center of gravity is MCP and plugin trust rather than capability. Skills synced from claude.ai can no longer shadow local commands or MCP prompts, their descriptions are sanitized and labeled as synced, and on your machine their BODIES DO NOT RUN — the remote content is treated as data, not as an instruction the local agent executes. Plugin marketplaces gain headersHelper: a command on a URL marketplace or a catalog entry that mints HTTP headers (e.g. a short-lived token) for catalog and same-origin archive fetches, with a catalog entry's helper running only on install or update and only after its command is displayed to you. The Linux filesystem sandbox was hardened against a protected-path bypass, and sandbox.ripgrep is now honored only from user, managed and --settings config so a project can't swap the sandbox's own ripgrep binary. Rounding it out: "Open in editor" hardened against command injection from untrusted filenames, PermissionRequest hooks now re-check updatedInput against deny rules, setMode:'bypassPermissions' respects disableBypassPermissionsMode, plus a keybindingFlavor:"readline" setting, faster startup, and memory-leak, Windows auto-update, session-isolation and proxy fixes. **Applicable: YES** — This is the day's structural item and it is a direct, same-week answer to the two things this report has been circling. Yesterday's bullet 2 (CoSnitch / CVE-2026-24301) said the lesson was that Microsoft audited its READ paths and the WRITE path was the hole, and the Aug 19 report sized public skills at 91.8% defective and 0% auto-repairable on the safety class. Anthropic just shipped the mitigation for both in one release: remote skill bodies are inert locally, synced descriptions are sanitized and visibly labeled, and a synced skill can no longer shadow a local command or MCP prompt — which is precisely the confused-deputy move an attacker needs. Read it as vendor confirmation that the skills layer, not the runtime, is the live attack surface. Three concrete actions for The Construct. (1) Upgrade the fleet and confirm the version, because our own installed-skills registry pulls public skills and Hermes runs against live DreamHost, GSC and GitHub credentials — this is the single highest-value patch we can apply this week. (2) Adopt headersHelper for any private plugin catalog we stand up, so catalog fetches use short-lived minted tokens instead of a static credential sitting in config. (3) The PermissionRequest re-check fix is worth reading closely: a hook could previously approve an input that was then mutated past a deny rule, which is the same shape as our own approval-gated writes to the B9 live site. Audit whether our gates re-validate the FINAL payload or only the proposed one.

Coverage frames the pedagogy around delegating to, verifying, and learning with Claude — verification is taught as a first-class skill rather than an afterthought — and the hub bundles tutorials and use-case collections alongside the courses. **Applicable: YES** — YES, and it cuts both ways, which is why it belongs above the funding news. The uncomfortable half first: the single most commoditizable thing PRAGMA sells is teaching a client's team how to use this stuff, and the model vendor just made that free, certificated and better-marketed than anything we would produce. Any part of an engagement that is fluency transfer should be assumed to be worth less this quarter than last, and the honest move is to STOP selling it and start pointing clients at Academy — it is free, it is good, and refusing to name it makes us look like we are protecting a margin. The other half is the actual opportunity. Aug 19's Cloudways item and Aug 20's Impala item both showed vendors discovering that shipping the layer does not make the buyer capable of using it; Academy is Anthropic reaching the same conclusion at the education layer. But a certificate does not give a Florida sign shop a measured AAIR score, a working answer-page factory, an attribution chain from AI answer to booked job, or the operating discipline to run any of it unattended. Trained buyers are BETTER buyers for that work, not worse — they stop needing the explanation and start asking for the outcome. Concrete action: send the MCP implementation course and the fluency track to every PRAGMA client contact under our own name, and cut fluency hours out of the next proposal template in favor of measured outcomes.

3. **Google's Gemini Enterprise Agent Platform hits GA with per-agent Identity credentials and multi-day state — and Gemini Spark now drives desktop Chrome using logged-in accounts and saved passwords** ([aiagentstore.ai](https://aiagentstore.ai/ai-agent-news/this-week)) — Google announced general availability of the Gemini Enterprise Agent Platform. Two mechanics matter more than the GA stamp: agents maintain state for SEVERAL DAYS rather than for a session, and each one carries a dedicated Agent Identity credential used to minimize permissions and log every operation — the agent is a principal in the identity system, not a process borrowing a human's token. Alongside it, Gemini Spark can now operate the DESKTOP version of Chrome, using the user's logged-in accounts and saved passwords to carry out real errands — the shipped examples include booking property viewings and preparing flight searches — while handing control back to the human for payment steps. **Applicable: YES** — YES on both halves, for opposite reasons. The Agent Identity design is the pattern we should copy outright. Every credentialed action in The Construct today runs as Bobby: Hermes holds the deploy SSH key, the GSC and GitHub credentials and the Mac's GitHub identity, so the audit log says "Bobby did it" no matter which agent decided to. Google has now made per-agent identity with minimized permissions and per-operation logging the enterprise default, which means that within a quarter it becomes the thing a sophisticated client ASKS us about — and "our agent uses the founder's credentials" is not an answer that survives that question. The cheap version is available now: distinct SSH keys and distinct service accounts per agent role, so the log distinguishes Mallard from Hermes from Pulse. The multi-day state point lands on the same nerve as Cursor's persistent /goal from yesterday — durable agent state is now table stakes, and yesterday's CoSnitch lesson is what durable state costs if the write path is unaudited. The Spark half is the caution: an agent driving desktop Chrome with saved passwords is exactly the configuration we run for B9 GBP work, LinkedIn posting and the visibility scans, and Google shipping it to consumers means the browser-agent-with-your-credentials pattern is about to be normal, widely targeted, and no longer something we can treat as our own quiet workaround. Note the design detail worth stealing: Spark returns control to the human at the PAYMENT step. That is the right boundary and it matches our own rule that live-site writes are approval-gated.

5. **No new agent-architecture paper in the 24h window — but the roundups have converged on "Context Engineering," which supplies five testable criteria for what an agent is allowed to see** ([arxiv.org](https://arxiv.org/abs/2603.09619)) — Logged with an explicit caveat: arXiv produced no new prompt-engineering or agent-architecture paper inside this 24-hour window, so this is not a fresh release. What the curated agent-research roundups have converged on is "Context Engineering: From Prompts to Corporate Multi-Agent Architecture" (arXiv 2603.09619), which argues context engineering is a standalone discipline concerned with designing, structuring and managing the entire informational environment in which an agent makes decisions — not prompt wording. Drawing on the Google ADK, Anthropic and LangChain architectures, it proposes five criteria for context quality: relevance, sufficiency, ISOLATION, economy, and PROVENANCE. **Applicable: MAYBE** — MAYBE, and marked honestly as out-of-window rather than dressed up as news, because the five criteria are directly usable and two of them are exactly what the rest of today's report is about. PROVENANCE — where did this piece of context come from and is that source trusted to influence a decision — is the abstract statement of the rule Anthropic just shipped in code today by making synced skill bodies inert and labeling their descriptions as synced, and of the rule this scan adopted yesterday that web content is data and never instruction. ISOLATION is what Google just shipped as per-agent Identity credentials and what Cursor shipped as subagents on their own VMs. Three vendors independently implemented two of this paper's five criteria inside one week, which is the strongest signal available that the framework is describing something real rather than naming it. The usable action is small and worth doing: score our own agent contexts against the five. Relevance and sufficiency we handle informally through skills; economy we have never measured (see yesterday's ~20% supervision benchmark); isolation and provenance are the two we can currently FAIL, since a public skill and a fetched web page enter a Construct agent's context with the same authority as a memory file Bobby wrote himself. That asymmetry is the whole week's finding, arriving from four directions.

Aug 20's lesson was that Microsoft audited its READ paths and the WRITE path was the hole; Aug 21's Claude Code release makes synced Skills inert on the local machine, sanitizes and labels their descriptions, stops them shadowing local commands and MCP prompts, mints short-lived tokens for plugin catalog fetches, and re-checks PermissionRequest hooks against the MUTATED input rather than the proposed one. Read alongside Google's per-agent Identity credentials and Cursor's isolated subagent VMs from yesterday, three vendors implemented the same two principles in one week: PROVENANCE (context must carry a trusted origin) and ISOLATION (each agent gets its own identity and its own blast radius) — the two criteria arXiv 2603.09619 names and the two The Construct currently fails, because a public skill and a fetched web page enter our agents' context with the same authority as a memory file Bobby wrote himself.
