6. **CORPUS GAP — Anthropic shipped scheduled memory consolidation for agents in MAY, calls it Dreams, and this corpus has never once mentioned it across 57 files** ([venturebeat.com](https://venturebeat.com/technology/anthropic-introduces-dreaming-a-system-that-lets-ai-agents-learn-from-their-own-mistakes)) — Anthropic introduced "dreaming" for Claude Managed Agents at Code with Claude on May 6: a scheduled offline process that runs BETWEEN agent sessions, reads the agent's existing memory store together with the transcripts of past sessions, and writes back a reorganised version — merging duplicates, deleting what it judges outdated, and surfacing patterns ("this user keeps making the same mistake," "this workflow always loops on step 3"). Anthropic's own analogy is hippocampal memory consolidation, the brain replaying the day and deciding what to keep, and it can be configured for automatic update or manual review. Harvey, the legal-AI startup and an early tester, reported task-completion rates rising roughly 6x once dreaming was on. It shipped alongside two siblings: `outcomes`, a self-grading loop where a separate evaluator scores the agent's output against a written rubric, and multiagent orchestration, where a lead agent fans work out to specialist subagents. Outcomes and orchestration went to public beta; Dreams stayed in research preview behind an access request, and has been quietly widened since — the platform release notes add Fable 5 and Sonnet 5 support on Jul 10 and Opus 5 on Aug 1. **Applicable: YES** — and this is the largest corpus gap this report has found, not because the feature is obscure but because it is the vendor-native form of something Bobby already built by hand and runs every day. `praxis-inbox.md` is a memory store. The `self-improving-loop` skill is a consolidation process. This very file is a transcript of past sessions. The whole architecture — capture the correction, write the lesson, feed it back so the mistake does not repeat — is dreaming, implemented manually, with a human scheduler and no evaluator. Three specific reads follow. First, `outcomes` is the falsification step from bullet 3 already built and in public beta: a separate evaluator scoring output against a written rubric is exactly the adversary this report concluded it lacks, and it does not need to be invented. Second, Dreams addresses a real decay in our own loop — the PRAXIS inbox only ever appends, so it grows monotonically and nothing merges duplicates or retires stale lessons, which is the failure mode ACE calls context collapse arriving from the opposite direction to brevity bias. Third, the honest caveat: Dreams is research-preview, access-gated, and scoped to Managed Agents rather than to Cowork or Claude Code sessions, so the near-term move is to steal the DESIGN — a scheduled consolidation pass over the inbox that merges and retires rather than only appends — not to wait on the feature. Note also the security literature that grew up around this feature: a memory store that rewrites itself between sessions is a persistence surface, and anything that reaches the transcript reaches the next session's premises.
