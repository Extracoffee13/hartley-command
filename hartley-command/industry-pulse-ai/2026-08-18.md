1. **CORRECTION — the MCP 2026-07-28 spec has no October SDK deadline: all four Tier 1 SDKs shipped stateless on July 28, and the deprecation window is a formal twelve-month minimum** ([blog.modelcontextprotocol.io](https://blog.modelcontextprotocol.io/posts/2026-07-28/)) — Verified against the primary release post and changelog. The spec is final and the protocol core is stateless: the initialize/notifications-initialized handshake and the Mcp-Session-Id header are retired (SEP-2575, SEP-2567), every request self-describes via _meta, and an optional server/discover RPC replaces up-front capability negotiation, so any request can land on any instance behind a plain round-robin load balancer. Three things this report previously got wrong or missed. (1) There is NO ~Oct 6 Tier 1 SDK deadline — TypeScript, Python, Go and C# all shipped 2026-07-28 support on release day, with Rust in beta; the real clock is a formal deprecation policy with a TWELVE-MONTH minimum window, so Roots, Sampling, Logging and the legacy HTTP+SSE transport are deprecated but supported into roughly July 2027. (2) Sampling, elicitation and roots/list are not simply gone — they are replaced by Multi Round-Trip Requests (SEP-2322), where the server returns resultType 'input_required' and the client retries with inputResponses attached, no held-open stream. (3) Streamable HTTP now REQUIRES the Mcp-Method and Mcp-Name headers (SEP-2243), list results carry ttlMs and cacheScope (SEP-2549), Dynamic Client Registration is deprecated in favour of Client ID Metadata Documents, and clients must validate the RFC 9207 iss parameter. Tasks and MCP Apps are now formal extensions rather than core. **Applicable: YES** — The correction is the point. This morning's fire made the MCP spec the founding entry in the deprecation calendar and stamped it with a ten-week validation window ending ~Oct 6 — a date that does not exist in the source. Building a governance artifact on a fabricated deadline is worse than having no calendar, because it manufactures false urgency in October and false safety afterwards. Corrected line item: MCP legacy surface end-of-life is ~July 2027 on a twelve-month minimum policy, not October 2026. Four real actions follow. First, any MCP server we author is stateless-first from today and mints explicit handles from tools rather than relying on transport state. Second, the mandatory Mcp-Method / Mcp-Name headers are the genuinely breaking change for anything sitting behind a gateway or WAF — that is a code change, not a policy note. Third, MRTR is good news we had written off: mid-call user confirmation survives statelessness, which is exactly the approval-gate shape Mallard and the ANS engine queue need, so agent designs that assumed sampling was dead should be revisited. Fourth, MCP Apps — servers shipping sandboxed interactive HTML that hosts render, with UI actions routed through the same audit and consent path as tool calls — is a live product surface for PRAGMA client dashboards, and it is now a stable extension rather than an experiment.
